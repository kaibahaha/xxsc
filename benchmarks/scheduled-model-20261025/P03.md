# P03｜带依赖与容量上限的确定性批调度

difficulty: 4/5
deliverable: results/scheduled-model-20261025/P03.py
entrypoint: schedule(jobs, completed, capacity)

## 任务
实现 `schedule(jobs: list[dict], completed: list[str], capacity: int) -> dict`。
每个 job 形如 `{"id":"a","depends":[],"cost":2,"priority":5}`。
- id 非空字符串且唯一；depends 为**无重复**的 job id 字符串列表（只允许引用 jobs 中定义的 id）；cost 为 1 到 capacity 的整数；priority 为任意有符号整数。
- completed 是已完成 job id 的**无重复**列表，必须都在 jobs 内；已完成 job 不再安排到新批次，但可满足后继依赖；信任 completed 状态，无须检查其自身是否满足依赖。
- capacity 为正整数；所有整数都拒绝 bool。
- **整个 jobs 依赖图必须无环**，即使环里的作业已标记 completed 也应抛 ValueError；缺失引用、自环、重复依赖、重复 ID、错误数据均 ValueError。

安排规则精确如下：按波次推进。某波次的候选 job 必须尚未完成、且所有 depends 在**该波次开始前**就已完成（本波次执行的作业不能立即解锁同波次其他作业）。候选按 `(-priority, id)` 排序；依次遍历，每个 cost 能放进当前剩余 capacity 就放入，不够就跳过，继续尝试后面的候选。将选中 job 按**实际选择顺序**记入当前波次；选中的作业仅在**下一波次**可作为已完成依赖。重复直到所有 job 完成。若出现剩余任务但本波次一个都无法安排，抛 ValueError。

返回：
```python
{"waves":[{"job_ids":["a","d"],"load":3}, ...], "total_waves": 2}
```
当 jobs 都已完成或 jobs=[] 时，waves=[]，total_waves=0。函数不得修改输入。

## 样例
```python
jobs=[
 {"id":"a","depends":[],"cost":2,"priority":5},
 {"id":"b","depends":[],"cost":2,"priority":4},
 {"id":"c","depends":["a"],"cost":1,"priority":10},
 {"id":"d","depends":[],"cost":1,"priority":3},
]
schedule(jobs,[],3)
```
期望：
```python
{"waves":[
 {"job_ids":["a","d"],"load":3},
 {"job_ids":["c","b"],"load":3}
],"total_waves":2}
```
强调：这是按规定贪心，不要求寻找全局最少波次的 NP-hard 最优方案。可用拓扑检查 O(V+E)，按每轮扫描/排序实现，清晰解释复杂度即可。
