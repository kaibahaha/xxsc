# R01 contract freeze — schema 2.0

Import with `from factory.agl.contracts import ...`; all data types are keyword-only
frozen dataclasses in `schemas.py`, with `to_dict` / `from_dict`. JSON is canonical
UTF-8 with sorted keys, no whitespace, no NaN. Lists are serialized JSON arrays.
Event producer is the agent identity; `provider_id` is separately bound by authentication.
No input `agent_id`, status, evidence reference or JSON flag proves authentication.

Core credentials go to an injected Authenticator; it must validate a real credential
and return ProviderSession. Do not expose this trusted in-process boundary directly
as a client-controlled session object. Registry admin can change admission only after
actual probe evidence is verified by the integration service. Local tests use mock identities.

ProviderAdapter operations return `status` from SUPPORTED/UNSUPPORTED/UNKNOWN/BLOCKED
plus operation-specific evidence. Git receipts carry repo/ref/path/blob_sha/commit_sha/
hash/error_code. UNKNOWN_WRITE requires read-only reconciliation before retry.
These Protocols freeze signatures, not an implemented Git transport.

LeaseGrant is local authority only after atomic commit. Before cross-cloud execution,
WorkBuddy must publish and independently reread its authoritative grant. There is no
cloud grant/publish implementation in R01. Cloud deployment remains BLOCKED_ATOMIC_LEASE.
ACK is per `(event_id, agent_id)` and requires a stored processing receipt and matching
event digest. External effects need the same idempotency key at their own sink; core
cannot make a remote HTTP effect exactly-once with a local database transaction.

V4.1 JSON Schemas remain read-only; `schemas.import_v41` provides an explicit boundary
for Task/Event/Receipt/Note. Legacy payloads are not directly executable grants.
M02/M06/M08/M10 implementations, CLI, packaging and scheduling remain WorkBuddy-owned.

## Core usage and deployment boundary

From the repository root (Python 3.11+):

```sh
python -m pip install pytest jsonschema
PYTHONDONTWRITEBYTECODE=1 python -m pytest factory/tests/core -v
PYTHONDONTWRITEBYTECODE=1 python -m factory.agl.contracts.demo
```

The package is a Python namespace package: `factory.agl`; no packaging/CLI files
owned by WorkBuddy were changed. Runtime core uses only the Python standard library.
`jsonschema` is required only by `import_v41` and compatibility tests.
`core.schema.json` is generated by `python -m factory.agl.contracts.generate_schema`.
It validates structure; dataclasses and Controller enforce semantic constraints.

Controller startup pins initial registry, quotas and simulation mode in its genesis
record; restarts pass that same initial registry. Runtime additions live in the log.
Every new Controller instance starts with a local UNKNOWN board fence. A trusted
controller_admin reads `board_digest()` then calls `reconcile_board(credential, new_key,
digest)`. This is a local compare-and-set; a Git adapter must additionally verify
actual projection receipts before calling it. An old successful reconcile request
cannot prove freshness after a new state change.

Use `claim(credential, unique_command_id, ClaimProposal(...))`, then check both
`status == GRANTED` and `authority == LOCAL_SQLITE_ONLY`. Local grants cannot authorize
cross-cloud execution until R02 supplies a verified durable deployment and publication.
After uncertain writes, use the returned command_id/reconcile_request in
`backend.reconcile(...)` and read the current lease. Do not blindly create a new
attempt. Terminal rejections are idempotently recorded; corrected requests use new keys.

`backend.records()` exports canonical immutable records; `rebuild(records)` computes
identical state without callbacks. `SQLiteLeaseBackend.restore(new_path, records,
expected_head_hash=trusted_receipt_hash)` restores into an empty DB and verifies readback.
Pin that hash through a trusted Git receipt: a hash chain alone is not authentication.
SQLite files, WALs and SHMs must never be committed or shared between cloud hosts.
The journal is replayed on each transaction (O(history)); this is a correctness MVP,
not a claim of production throughput. A persistent DB implementation must preserve
transaction + idempotency + fencing + journal atomicity before replacing this backend.

Diagnostic snapshot/backend methods are trusted in-process service APIs and contain
all state. Never expose them directly to untrusted clients; implement scoped reads in
the adapter. `TaskSpec.read_paths`/`write_paths` use normalized relative path prefixes,
including a slash boundary, and are checked for lease eligibility. The actual Git
adapter must enforce the same scopes on each external write and independent readback.
All controller credentials are excluded from journal records.

Scoped FAIL notes block further acceptance of that exact task/spec/commit. A new
candidate commit requires rerun; automatic retraction of FAIL or readmission of an
unavailable identity is deliberately left for an explicit reviewed integration policy.
