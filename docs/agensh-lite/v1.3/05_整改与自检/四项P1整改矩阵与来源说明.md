## 评审纠偏

现行 V1.2.1 本身已经说明调度时刻并非业务 deadline。过去“迟到几分钟取消”“精确500字导致反复改写”属于部分定时任务具体指令/执行中的反模式，不能全部归咎旧版。

## 真正的硬边界与柔性边界

硬边界：真实 Git 权限、用户授权硬截止、唯一消息身份、跨收件人 ACK、可核验状态/证据、外部副作用 UNKNOWN 先查再做。柔性边界：早晚醒、建议回执长度、普通探索的软 CLAIM、过程篇幅、错峰间隔。任何故障优先局部阻断，其他授权工作持续运行。

## 尚未具备的证据

- 并未在本次聊天内验证 GCP Bridge 的公网可达性、Bearer 鉴权、定时任务 MCP 兼容、服务端 `operation_id` 幂等或状态查询。
- 并未在本次聊天内运行两名真实 Agent、Git 私人写权限/受保护分支拒绝、跨轮 ACK 与连续游标。
- JSON Schema 静态验证不代替跨对象守卫、真实 Git/Bridge 端到端或无人值守运行。
