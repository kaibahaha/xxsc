# V1.2.1 → V1.3-DRAFT 逐章修订及“过度刚性约束”清理表

状态：**PROPOSED / 尚未生效**。旧版三卷未被覆盖。此表必须和《微软逐条对照》一起审核，不能仅凭文字修订声称工程通过。

> **事实校正**：V1.2.1 第二卷 §5 第161行其实已经明确写着“调度时间不是业务deadline”；因此“迟到几分钟就取消”主要来自用户此前某些**实际定时任务指令或Agent自行附加的执行条件**，不是现行三卷全文都持有此错误。类似地，“500字必须精确计数”是用户经历过的运行反模式，不能伪称 V1.2.1 有一条已发现的500字硬阈值。V1.3 的价值是把这些原则提升成明确的防误停机禁例，并清理其余过度细分的门槛。

## 一、先判定什么可以成为 HARD

| 问题 | 推荐分类 | 理由 | 出错后处理 |
|---|---|---|---|
| 计划10:10、实际10:13 | **SOFT** | 微软错峰是调度策略，不影响事件效力；定时是拉取时机 | 继续读/做；记录实际时刻 |
| 提前3分钟，没有新的Task | **SOFT** | 任务未来仍可能发布；闲置不是失败 | 继续旧任务或等下一次 |
| 某次跑了12个检查动作中的10个 | **SOFT** | 微软核心是五步循环，允许一个任务跨多个回合 | 保存交接，下一轮继续 |
| 建议500字，实际700字 | **ADVISORY** | 正常文本长度不是交付真伪和安全因素 | 直接提交，之后风格优化；绝不多轮字数重算 |
| ChatGPT回执建议≤200字 | **ADVISORY** | 历史会话确实需控量，但精确数数伤害效率 | 正常一两句；不计数、不因多字失败 |
| 软CLAIM重叠 | **SOFT** | 微软鼓励冲突协商，而非网络排他 | 消息协调；个别候选不合并 |
| 失败2次就关掉所有任务 | **SOFT** | 限次退避只适用于该事件/任务，非全局停机 | 单项提示、升级或换策略，其他任务继续 |
| 已明确真实总预算/截止到了 | **HARD** | 用户授权/实验上限明确；论文原版也有六小时边界 | 停止越期生产写；只读核验仍可继续 |
| 凭据/平台API明确拒绝 | **HARD** | 无权不应尝试绕过 | 阻断对应写入，留下证据 |
| 外部副作用UNKNOWN | **HARD for retry** | 重发可能造成重复删除/收费/文件创建 | 只读对账；停止该副作用的盲重试 |
| 把测试未跑说成PASS、旧SHA审核当新SHA | **HARD for claim/merge** | 直接损害事实真实性和正式代码正确性 | 拒绝“已通过/已合并”声明，继续研究和修复 |

**设计判据**：如果只是为了格式、时间整齐或报告方便，且没有真实业务损失，就不能导致全局停机。仅用户真实授权/不可逆风险/事实真实性可以阻断对应操作。

## 六、简洁原则的最小验收

- **文档层**：3卷职责不重叠，项目定位/五步循环/事件与定时关系一致；没有新增中央任务分派器，没有把微软的参数误当全局死条件。
- **编排层**：计划时刻早/晚几分钟仍可处理有效事件；输出字数超建议不阻断；一轮未完成的任务能下一轮继续。
- **传输层**：真实共享发布可见、按身份去重、错误重试/补扫、未知副作用先查、Git读不到≠没有事件。
- **安全层**：真实权限拒绝、用户明确生产禁写截止、测试未完成、外部不可逆操作UNKNOWN，仍只阻断受影响动作。
- **来源层**：每条机制能指向论文 §/代码文件，标明 `MS/ADAPT/LOCAL/NOT_SUPPORTED`，不把理论推导当已实测。

**回滚/生效要求**：V1.3 候选需经用户明确确认后才能成为现行章程。若批准，先决定源文件保留/文件身份的迁移方式，再形成从 V1.2.1 机器对象到 V1.3 的明示兼容政策；未完成测试不得宣称新 Schema 已在系统启用。
